# Google Sheets-Based Digital Marketing Ops MVP

## Executive Summary

Build a complete team management app using **React + Vite + Google Sheets API** as the backend. Client-centric design where all work (shoots, assets, calendar) is linked to clients. Real-time collaboration through Google Sheets. 5 role-based dashboards with clear workflows.

## Technology Stack

- **Frontend**: React 18 + Vite
- **Backend**: Google Sheets API v4 (9 sheet tabs as database)
- **UI**: TailwindCSS + shadcn/ui components
- **Charts**: Recharts
- **Calendar**: react-big-calendar
- **Auth**: Google OAuth 2.0
- **Deployment**: Vercel

## Decision: Google Sheets for MVP

**Why Google Sheets:**

- ✅ 30 min faster setup (data already exists)
- ✅ Sufficient for MVP scale (5-20 users, <1000 rows/sheet)
- ✅ Team can verify data directly in Sheets
- ✅ Easy migration path to Supabase later
- ✅ Real-time collaboration built-in

**Data Transmission Strategy:**

- **Primary Method**: Smart Polling (30-second intervals, only active pages)
- **Optimization**: Debounced updates (batch changes)
- **Future**: WebSocket/SSE when migrating to Supabase

### How Everything Connects

**Client-Centric Model:**

```
Client
  ├── Projects (implicit, via shoots/assets)
  ├── Shoots (photographer work)
  │     └── Shoot Attendance (clock in/out)
  ├── Assets (editor tasks)
  │     └── Editor Time Logs
  │     └── Asset Comments
  └── Content Calendar (publishing schedule)
        └── Links to Assets
```

**Relationships:**

- `Shoots.client_id` → Links shoot to client
- `Assets.shoot_id` → Links asset to shoot (and thus client)
- `Content_Calendar.asset_id` → Links calendar to asset (and thus client)
- `Photographer_Attendance.shoot_id` → Links attendance to shoot
- `Editor_Time_Logs.asset_id` → Links time to asset

## Global System Flow

### How Data Flows Through the System

**1. Client Creation Flow:**

```
Lead adds client
  → Form submission
  → SheetsAPI.appendRow('Clients', clientData)
  → Google Sheets updated
  → DataContext.refreshData('clients')
  → All dashboards update (if viewing clients)
```

**2. Shoot Assignment Flow:**

```
Manager/Lead creates shoot
  → Form: shoot_name, date, photographer_id, client_id
  → SheetsAPI.appendRow('Shoots', shootData)
  → Photographer sees shoot in their dashboard
  → Photographer clocks in
  → System creates Photographer_Attendance record
  → Lead sees "Photographer on shoot" in dashboard
```

**3. Asset Workflow:**

```
Shoot completed
  → Lead creates asset from shoot
  → Asset linked to shoot (and thus client)
  → Asset assigned to editor
  → Editor sees in "To Edit" column
  → Editor starts editing (time log created)
  → Editor uploads revision
  → Editor marks "Ready for Review"
  → Creative Lead sees in Approvals
  → Creative Lead approves
  → Asset status → "Completed"
  → Lead adds to Content Calendar
  → Calendar entry linked to asset (and thus client)
  → Everyone sees in calendar view
```

**4. Content Calendar Flow:**

```
Lead adds calendar entry
  → Selects client
  → Selects asset (from that client's assets)
  → Sets publish date, channel, time
  → System adds to Content_Calendar sheet
  → Calendar entry shows:
   - Client name
   - Asset title
   - Channel icon
   - Status (scheduled/published)
  → All users see in calendar view
  → When asset completed, calendar updates
```

**5. Team Visibility Flow:**

```
Photographer clocks in for shoot
  → System updates Photographer_Attendance
  → Lead dashboard queries:
   - Active shoot attendance (status = "In Progress")
   - Joins with Shoots table (get client_id)
   - Joins with Clients table (get company_name)
  → Lead sees: "Chris → Acme Corp Product Shoot (2h active)"

Editor starts editing asset
  → System updates Editor_Time_Logs
  → Lead dashboard queries:
   - Active time logs (end_time is null)
   - Joins with Assets (get title, shoot_id)
   - Joins with Shoots (get client_id)
   - Joins with Clients (get company_name)
  → Lead sees: "Maya → Acme Corp Logo Redesign (1.5h active)"
```
